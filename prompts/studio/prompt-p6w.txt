Use IDKit (World ID 4.0) in staging with the app id WORLD_APP_ID and the rp id WORLD_RP_ID from the backend environment. The credential is CredentialRequest("proof_of_human"), always passed through .constraints(...), never a preset. Sign every request on the backend with WORLD_SIGNER_KEY using signRequest from @worldcoin/idkit-core/signing, fresh for each request, and never send the key to the browser. Pass the signature to the browser as rp_context { rp_id, nonce, created_at: createdAt, expires_at: expiresAt, signature: sig }. There are two World ID steps. Step 1, once, when the user presses "Set budget {amount}": sign without an action, and the browser calls IDKit.createSession({ app_id, rp_context, environment: "staging" }).constraints(CredentialRequest("proof_of_human")). The backend forwards the result unchanged to POST https://developer.world.org/api/v4/verify/{rp_id}, and on success saves the full session_id against the budget and the screen reads "Budget set." Never replace a saved session_id silently. Step 2, each time the user presses "Hold {amount} for this job": the backend saves a pending hold (hold id, amount, job id) and does not create the hold yet. It signs a request without an action. The browser calls IDKit.proveSession(saved session_id, { app_id, rp_context, environment: "staging" }).constraints(CredentialRequest("proof_of_human", { signal: "{hold id}:{amount}" })). The backend forwards the result unchanged to the same verify endpoint. It accepts the approval only when every check below passes. On the verify response: success is true and environment is "staging". On the IDKit result: environment is "staging", nonce is the one it signed for this pending hold, session_id is exactly equal to the saved one as a whole string, responses[0].signal_hash equals hashSignal("{hold id}:{amount}") from @worldcoin/idkit-core/hashing, and responses[0].session_nullifier[0] has never been accepted before (compare and store nullifiers as 256-bit integers). Then, in one database transaction, it stores that session nullifier and creates the hold, and the screen reads "Held {amount} for this job." The request must be completed within 2 minutes. A pending hold that is not approved within 2 minutes is closed at once. A cancelled request, a request not completed in time, a failed verify, a different session, a mismatched signal, or a reused session nullifier creates no hold, and the screen reads "Not approved. Nothing was held or paid." Stop polling when that happens. While waiting, the screen reads "Waiting for approval in World ID."
