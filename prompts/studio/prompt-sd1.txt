Write, test and deploy one Solidity contract named SealedDelivery on Arc testnet. It adds a dispute path to x402 nanopayments. The buyer signs a normal x402 payment. The seller verifies it, returns the response encrypted together with a signed Promise that names the buyer's payment nonce, settles through Gateway off this contract, and gives the decryption key on a separate request. The contract never receives the payment. It only holds a deposit that each seller chooses to put in.

Types:
Promise { address seller; uint256 value; bytes32 paymentNonce; bytes32 keyHash; bytes32 plaintextHash; bytes32 ciphertextHash; uint64 expiry }, signed by the seller with EIP-712 under the domain name "SealedDelivery", version "1", this chain id and this contract.
PaymentAuth { address from; address to; uint256 value; uint256 validAfter; uint256 validBefore; bytes32 nonce }, signed by the buyer as an EIP-3009 TransferWithAuthorization under the EIP-712 domain name "GatewayWalletBatched", version "1", chain id 5042002, verifying contract 0x0077777d7EBA4688BDeF3E311b846F25870A19B9.

Functions:
claim(Promise, sellerSignature, PaymentAuth, buyerSignature). It requires a valid seller signature from promise.seller, a valid buyer signature from auth.from, msg.sender == auth.from, auth.to == promise.seller, auth.value == promise.value, auth.nonce == promise.paymentNonce, block.timestamp < promise.expiry, promise.expiry <= block.timestamp + MAX_EXPIRY, and no earlier claim for that nonce. It sets the answer deadline to now + ANSWER_WINDOW and reserves min(promise.value, coverage(seller)) of the seller's deposit.
answer(paymentNonce, key). Before the deadline, it requires keccak256(abi.encodePacked(key)) == keyHash, otherwise it reverts with WrongKey. It marks the claim DELIVERED, releases the reservation and emits KeyRevealed(paymentNonce, key). Anyone holding the key may call it.
finalize(paymentNonce). After the deadline on an open claim, anyone may call it. It marks the claim SILENT, moves the reservation from the seller's deposit to the buyer's claimable balance, adds one to silentCount[seller] and emits Silent(paymentNonce, seller, buyer, paidOut).
deposit(amount), requestWithdraw(amount), withdrawDeposit() and withdrawClaimable(). Withdrawals are pull only. A requested withdrawal can complete only after COOLDOWN, and COOLDOWN must be at least MAX_EXPIRY + ANSWER_WINDOW. coverage(seller) = deposit - reserved - pendingWithdrawal. It is public, so a buyer can read it before paying.

MAX_EXPIRY, ANSWER_WINDOW and COOLDOWN are constructor arguments, so a demo can use 60 seconds and production can use days, with the COOLDOWN rule enforced in the constructor.

USDC: use only the ERC-20 interface at 0x3600000000000000000000000000000000000000 with 6 decimals, through SafeERC20. Never use payable or msg.value. State reads are public mappings and events only. Add no owner, no admin and no upgrade path.

Tests must cover each revert above, the wrong key, a claim replay, a seller signing for another seller, a buyer signature from someone else, a claim after expiry, a finalize before the deadline, an answer after the deadline, a withdrawal attempt before the cooldown, a withdrawal that would dip into a reservation, and a payout capped by coverage. Add a test that checks the buyer signature against this real EIP-3009 vector, and read the vector from context/eip3009-vector.json. Run the contract scan and fix what it finds. Deploy with MAX_EXPIRY 3600, ANSWER_WINDOW 60 and COOLDOWN 3660. Do not change the existing app in this turn. Report the address, the tests and the scan result.
